- [Pull Request №3](https://github.com/WhyNot-png/anime-data-engineering/pull/3).

- Время публикации: 6 ноября 2026, 15:52 по Москве.

Проверены граф CI/CD, многоэтапная сборка, тестовые фикстуры, изоляция
PostgreSQL и приёмочные API-сценарии. В отдельном Compose-проекте запущена
точная версия PR: **41 тест прошёл**, покрытие строк и ветвей — **83,86%**.

Замечания:

1. [Связать публикацию образа с runtime smoke-проверкой](https://github.com/WhyNot-png/anime-data-engineering/pull/3#discussion_r4492592942).
   Проверка запуска приложения выполняется в независимом workflow и не входит
   в зависимости job публикации. Предложено включить её в тот же граф `needs`.
2. [Сделать публикацию порта тестовой БД опциональной](https://github.com/WhyNot-png/anime-data-engineering/pull/3#discussion_r4492592949).
   Воспроизведён конфликт фиксированного порта 5433 при запуске двух тестовых
   Compose-проектов с разными именами.
3. [Удалять анонимный том при очистке test-db](https://github.com/WhyNot-png/anime-data-engineering/pull/3#discussion_r4492592956).
   Проверено, что удаление контейнера без флага удаления томов сохраняет
   анонимный том PostgreSQL. Предложена адресная очистка тестового контейнера
   и его тома без удаления рабочей БД.

Все три замечания отмечены как неблокирующие улучшения (`P3`).

Проверены HTTP-сервер, валидация, клиентская часть, построение и чтение индекса.
**93 теста прошли**, покрытие — **95,85%**; Ruff и mypy завершились успешно.
Использован тестовый encoder: веса ML-модели не скачивались,
качество релевантности поиска в рамках этого ревью не оценивалось.

Замечания:

1. [Обрабатывать RecursionError при разборе JSON](https://github.com/WhyNot-png/anime-data-engineering/pull/5#discussion_r4492593239) (`P2`).
   Воспроизведён обрыв соединения вместо ответа 400 для глубоко вложенного
   JSON размером 40 011 байт, который проходит ограничение 64 KiB.
2. [Ограничить HTTP-обработчики и ожидание заголовков](https://github.com/WhyNot-png/anime-data-engineering/pull/5#discussion_r4492593250) (`P3`).
   На отдельном сервере 16 незавершённых подключений создали 16 дополнительных
   потоков: размер backlog не ограничивает количество активных обработчиков.
3. [Согласовать проверку Unicode-длины на клиенте и сервере](https://github.com/WhyNot-png/anime-data-engineering/pull/5#discussion_r4492593260) (`P3`).
   В Chromium подтверждено: запрос из двух emoji проходит клиентскую форму,
   но получает 400 от API из-за различия UTF-16 code units и Unicode code points.
